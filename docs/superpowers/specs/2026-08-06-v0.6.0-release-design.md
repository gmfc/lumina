# v0.6.0 release cut — design

**Date:** 2026-08-06
**Branch:** `release/lumina-v0.6.0`
**Base:** `main` @ `871fb32`

A release cut, not a feature milestone. Twenty commits have accumulated on `main` since the
`v0.5.0` tag; this ships them as `v0.6.0`, establishes a changelog convention, and closes two
documentation gaps the unreleased work left behind.

---

## 1. Why 0.6.0 and not 0.5.1

Three of the twenty commits were authored as a "v0.5.1 perf pass" and never tagged. Since then
the branch also gained soft word wrap, a file-open policy with two size thresholds, a viewer
plugin contribution with two built-in viewers, and project-local configuration. Those are
additive features, so a patch bump would undersell the release. Nothing in the range is
breaking: every new setting defaults to its previous behaviour (`line_wrap = false`), and the
viewer contribution is additive to `plugin.toml`.

---

## 2. What is being released

Grouped as the changelog will present it.

### Added

- **Soft word wrap** — `Alt+Z` / `view.toggleWrap` / `line_wrap` config, off by default. Pure
  view state: the buffer, transactions, and char offsets are untouched; a logical line maps to
  one or more visual rows. New `editor-core/wrap.rs` (`wrap_segments`, `segment_of`) is the
  single source of truth; `ViewState` gains `wrap`/`wrap_width`/`scroll_sub`; `screen_to_char`
  and `char_to_screen` became wrap-aware; Up/Down move by visual row preserving the goal
  column, Home/End snap to the visual row.
  MVP limits, stated in the docs: no continuation indent, wraps at the pane width only, and
  inlay hints are not drawn under wrap. In Vim mode `j`/`k` follow the visual row like
  `Up`/`Down` while operator-pending motions such as `dj` stay logical — a known deviation
  from Vim, tracked in issue #54.
- **Large-file and binary handling** — `files::open` is a single chokepoint that probes the
  filesystem size plus the first 8 KiB before reading. `max_file_size_mb` (64) yields a notice
  tab with *Open Anyway* (`file.openAnyway`); `large_file_mb` (8) still opens the file but
  suppresses tree-sitter, the git gutter, and LSP, announced by a `LARGE` status segment.
  Binary refusals name the format and are not overridable, because those bytes cannot
  round-trip a UTF-8 rope.
- **File viewers as a plugin contribution** — `[[viewers]]` in `plugin.toml` claims extensions;
  `Plugin::render_viewer` publishes styled rows through the existing `PanelLine`/`Span`
  channel. No port exists for writing bytes back, so a viewer cannot become an editing path.
  Built-ins: `pdf` (object scanning rather than xref walking, `/Type /ObjStm` expansion,
  `/Pages`→`/Kids` ordering, `/ToUnicode` CMap decoding; adds the pure-Rust `flate2`
  dependency) and `hexview` (`Ctrl+K Ctrl+H`, capped at 256 KiB). `file.openAsText`
  (`Ctrl+K Ctrl+T`) means a viewer can claim an extension but never hold it hostage.
  `plugins/csvview` is the external worked example.
- **Notification log** — every notice is kept in a bounded log, reachable with `Ctrl+K Ctrl+N`
  / `view.notifications`.
- **Keybinding reference** — `help.keybindings` (`Ctrl+K Ctrl+R`) opens a sheet generated from
  the live keymap, so it includes plugin chords and `[keys]` overrides and cannot drift.
  Documented VS Code deviations head the sheet.
- **Project-local configuration** — `<root>/.lumina/config.toml` layers over the global file on
  the same precedent the plugin loader already set. `[settings]` and `[lsp]` win per key,
  `[keys]` apply last, `[plugins]` may disable but never force-enable. Both tiers hot-reload; a
  malformed tier is skipped with an error naming the file rather than dropping the tiers under
  it.
- **Conflict exits** — `file.reloadFromDisk` (confirmed; it discards edits and undo history)
  and `file.keepMine`.
- **Which-key** — an armed chord prefix lists its continuations in the status bar.

### Changed

- **`Ctrl+Q` now confirms.** `app.quit` set `quit = true` unconditionally, bypassing the
  dirty-tab guards `tab.close` and `tab.closeAll` both applied. It routes through a ConfirmQuit
  overlay naming the files at risk: save all & quit, discard & quit, or cancel. Sessions
  persist paths and cursors, not contents, so nothing else would have recovered that work.
  `:qa!` still force-quits.
- **Save As confirms an overwrite**, previews the absolute path a relative name resolves to,
  and reports a missing parent directory in the box instead of failing afterwards.
- **Notices are typed.** The single `Option<String>` status message became a `Notice` with a
  level: Info clears on the next keystroke as before, Warn and Error hold until superseded or
  dismissed with `Esc`, and the bar is tinted by level. Errors name their recovery using the
  chord actually bound to it, and `io::Error` kinds became sentences that name the file.
- **Persistent state has persistent segments** — `LARGE` and `CONFLICT` sit beside the encoding
  and line-ending segments rather than being announced once through a message that the next
  keystroke clears.
- **The caret diagnostic holds its own status segment**, separated and dimmed. When the bar is
  too narrow for both it and the message, `fit_left` shares the width by a stated rule instead
  of one silently winning.
- **The command palette shows live chords** and applies a bounded, decaying recency bonus —
  capped below what a tight contiguous match scores, so habit breaks ties but typing always
  wins. Recorded on activation, not on listing.
- **Overlays standardise on `Esc`**; a picker with no matches says so instead of rendering
  blank.

### Fixed

- **File-open policy holes** found by adversarial review: `head[4..8] == "ftyp"` had no box-size
  guard, so ordinary source lines (`int ftype;`) were refused as MP4; `FF FE 00 00` is the
  UTF-32LE BOM and was admitted as UTF-16 text, decoded to interleaved NULs, and would have
  written that mojibake back over the original on first save; six four-letter ASCII signatures
  refused prose beginning with those words. Mutation paths that reached a view tab's
  placeholder (bracketed paste, plugin edits, the right-click menu) are guarded at
  `App::with_doc` and `Host::apply_transaction`. `tab_view_key` swallowed chord continuations,
  killing every `ctrl+k` chord on exactly the tabs where the hex-view chord lives. The file
  watcher was a back door into the unbounded read.
- **PDF parser** — a quadratic hang in array/dict error recovery (`[` plus a megabyte of
  letters took over 60 s), an unbounded `/ToUnicode` CMap, a `u32` overflow in the `bfrange`
  array form, a `/Kids` cycle bounded only at 2^32 visits, `1e30 as usize` saturation, and
  unbounded `RunLengthDecode` chains.
- **The notification tab never showed its first message** — it decided staleness by comparing
  row counts, and the empty-log and one-message states have the same count. It now stamps
  itself with a monotonic notice sequence.
- Clippy 1.97 lints and two platform-fragile test assertions.

### Performance

- **Render** — decoration bucketing (`cell_style` scanned every published decoration for every
  character; now filters to the line's char range once into reused scratch — roughly 24× on the
  hot loop), reused style scratch buffers (~2×), and `Document::line_str` returning `Cow<str>`
  that borrows the rope slice when contiguous (~1.8×).
- **Idle-frame gating** — the ~60 Hz loop rebuilt the whole frame and re-ran caret and LSP
  recomputes every tick. It now repaints only on a real change, with carve-outs so the LSP
  diagnostics debounce and crashed-server restart backoff still fire while idle.
- **Input and LSP message paths** — cached lowercased completion labels (~1.9× on refilter),
  `classify` moving payloads instead of deep-cloning them, allocation-free event dedup, and a
  single-cursor fast path in `normalize`.

### Internal

Six commits splitting functions past SonarCloud's cognitive-complexity threshold, and a fix for
a stray `.profraw` failing the coverage job.

## 3. Changes this cut makes

### 3.1 Version bump

`Cargo.toml`, `[workspace.package]`: `version = "0.5.0"` → `"0.6.0"`. All six crates carry
`version.workspace = true`, so this is the only edit. `Cargo.lock` regenerates on the next
build.

### 3.2 `CHANGELOG.md` (new, repo root)

[Keep a Changelog](https://keepachangelog.com/) format, newest first, with the section content
of §2 above. Also backfilled so the file is not a stub:

- `## [0.5.0] — 2026-07-20`, from the annotated tag's four bullets (crate rename
  `editor-app` → `lumina`, zero-config LSP, the plugin-extensible context menu, the
  relative-path URI fix).
- `## [0.1.0] — 2026-07-08`, one line. The tag body is bare (`lumina v0.1.0`), so the entry
  says "Initial release" and links the tag rather than inventing history.

Compare links at the bottom of the file (`v0.5.0...v0.6.0`, `v0.1.0...v0.5.0`).

Entries are written in user-facing language, not commit subjects. Where a change closes a
defect that could lose work, the entry says what the old behaviour was — a user deciding
whether to upgrade needs that.

### 3.3 Release-notes wiring in `release.yml`

`softprops/action-gh-release` accepts `body_path` together with `generate_release_notes: true`;
it appends the generated PR list beneath the supplied body. So:

- A new step extracts the section matching `${GITHUB_REF_NAME}` from `CHANGELOG.md` into
  `release-notes.md`.
- The publish step gains `body_path: release-notes.md` and keeps `generate_release_notes: true`.
- If no matching section exists, the step writes an empty file and the release still publishes
  with auto-generated notes only. A missing changelog entry must not fail a release that has
  already built five binaries.

This makes the convention self-sustaining: future tags pick up their notes with no manual
`gh release edit`.

### 3.4 README — document word wrap

Word wrap is absent from the README: not in the key list, not in the `[settings]` sample. Add
`Alt+Z` to the key list and `line_wrap = false` to the config block, with a sentence naming the
MVP limits.

### 3.5 Settings tab — expose `line_wrap`

`crates/app/src/settings.rs` builds the Settings tab from an explicit entry list, and
`line_wrap` is not in it, so the README's claim that the tab covers "every `[settings]` option"
is false as of this release. Add a `toggle(...)` in the Editor section, next to `auto_pairs`
and `auto_indent`, plus a test asserting the entry is present and that toggling it writes
`line_wrap` back to `config.toml`.

Scope note: this is the only change to shipped application code in an otherwise mechanical cut.
It is included because it closes a claim the release itself would otherwise falsify, and
because the alternative — shipping the gap and fixing it in 0.6.1 — costs more than seven
lines.

## 4. Out of scope

- **`LICENSE` files.** `Cargo.toml` declares `license = "MIT OR Apache-2.0"` but no license
  file exists, and `release.yml` copies `LICENSE*` best-effort (`|| true`), so the published
  archives silently ship without one. Real, and deliberately deferred to its own change.
- Any new feature work. The next milestone is a separate brainstorm.

## 5. Verification

Run before tagging, under a hermetic `HOME` — the app test suite reads the real user config
otherwise and roughly seventeen tests fail on it:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p editor-core --features proptests \
  --test transaction_roundtrip --test selection_invariants --test coordinate_mapping
cargo test -p editor-builtins --features proptests --test self_hosting
```

These are the CI gates in `.github/workflows/ci.yml` and must be green at every commit.

Additionally, before the tag is pushed: a `workflow_dispatch` run of `Release`. It builds all
five targets and uploads archives as run artifacts without touching Releases, which exercises
the new notes-extraction step without publishing anything.

Manual check that the word-wrap docs match the build: `Alt+Z` toggles, and the Settings tab
shows the new toggle and writes `line_wrap` back to `config.toml`.

## 6. Sequence

1. Branch `release/lumina-v0.6.0` off `main` (matches the `release/lumina-v0.5.0` precedent).
2. Commit this spec.
3. Version bump, `CHANGELOG.md`, `release.yml` notes step, README, Settings toggle.
4. Run every gate green.
5. PR → review → merge to `main` (the repo is rebase-only, one PR per change).
6. `workflow_dispatch` dry run of Release on `main`.
7. Annotated tag `v0.6.0` on `main` with a short summary body, in the style of the `v0.5.0`
   tag. Push the tag.
8. `release.yml` builds the five targets and publishes the GitHub Release, its body taken from
   the changelog section with the auto-generated PR list appended.
9. Verify the published release: five archives plus `.sha256` files, and `install.sh` resolving
   `latest` to `v0.6.0`.

---

## 7. Risks

- **The notes-extraction step is new and runs only on a tag.** Mitigated by the
  `workflow_dispatch` dry run at step 6 and by the empty-file fallback, which keeps a
  malformed changelog from failing a release whose binaries already built.
- **`Cargo.lock` churn.** The v0.5.0 bump touched roughly 70 lock lines. Expected, and the
  release build uses `--locked`, so the lock must be committed in the same PR as the bump or
  the build fails.
- **The Settings toggle is untested UI surface.** It follows the existing `toggle(...)` pattern
  exactly and the settings round-trip is already covered; a test asserting the entry exists and
  writes back keeps it honest.
